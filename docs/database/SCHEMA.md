# VISTA Firestore Schema

**Database:** `vista-teaching-lab` (Firestore Native, `northamerica-northeast1` / Montreal)
**Purpose:** isolated development, test and CI database. Synthetic data only.
**Canonical rules:** `firestore.rules` · **Indexes:** `firestore.indexes.json`

This document is the authoritative description of the data model. Every collection,
field, type and invariant listed here is enforced by `firestore.rules` and/or
validated by `tests/seed-dataset.test.js`.

> **Privacy invariant.** No real staff data may ever be written to this database.
> Everything below is generated by `tools/seed/dataset.js` from a fixed seed.

---

## 1. Design principles

1. **Source / mirror split.** `sessions` holds the private source of truth.
   `calendar_sessions` is a public, allowlisted projection of it. The two must be
   field-equal after every write — enforced by `calendarMatchesSourceAfter()`.
2. **Private request split.** A change request is split across five collections so
   that each office sees only its own scope: public request, workflow routing,
   per-office approvals, private faculty target, append-only audit.
3. **Derived data is disposable.** `settings/*` indexes are rebuildable from
   `sessions` + `faculty`. Nothing authoritative lives there.
4. **Sanitized projections over broad reads.** Where a role needs to reference
   another person, it reads a sanitized derived document, never `/faculty` and
   never a raw `/users` list.
5. **Audit is append-only.** Every `*_log` / `*_audit` collection denies
   `update` and `delete` outright.

## 2. Identity

### `users/{uid}`

The account record. One document per Firebase Auth user.

**Access:** `get` is limited to the account holder and administrators; `list` is
Owner-only. Faculty-role accounts that need to reference a colleague read
`settings/people_index` (§8) instead. This closes the enumeration gap where any
faculty account could previously read every colleague's name, email, `facultyId`,
`active` flag and password-change state.

| Field | Type | Notes |
| --- | --- | --- |
| `name` | string | display name |
| `email` | string | institutional address |
| `role` | string | one of the explicit roles below |
| `facultyRoles` | list\<string\> | 1–3 of `hicc`, `visc`, `faculty`; forbidden on office accounts |
| `facultyId` | string | required when `role` is faculty-linked; must exist in `/faculty` |
| `active` | bool | inactive accounts fail every `ready()` check |
| `mustChangePassword` | bool | see §7 — UI guidance only, not a security control |
| `officeName` | string | ADFA/ADC/LAB display name, office accounts only |
| `officeEmail` | string | office accounts only |
| `updatedBy` / `updatedByName` | string | actor stamp |
| `updatedAt` / `createdAt` | timestamp | server time |

**Explicit roles:** `owner`, `administrator`, `other_office`, `adfa_general`,
`adfa_regular`, `admin`, `editor`, `viewer`, `hicc`, `visc`, `faculty`, `adc`, `lab`.

**Role → office mapping** (`officeForRole`): `adc`→ADC, `lab`→LAB,
`owner`/`administrator`/`admin`/`adfa_general`/`adfa_regular`→ADFA, everything else→none.

### `faculty/{facultyId}`

The Faculty Directory record. **Read access is restricted**: `admin()` or the
owner of the record (`ownFacultyId`). Ordinary faculty never read this collection
for anyone but themselves.

| Group | Fields |
| --- | --- |
| Identity | `firstName`, `lastName`, `email`, `ucid` |
| Appointment | `appointmentType`, `rank`, `currentTitle`, `expiryDate`, `fte` |
| Contract DOE | `doe`, `doeTeaching`, `teachingDOE`, `contractTeachingDOE` |
| Override | `doeOverride2026_27` (map: `value`, `reason`, `notes`), `overrideDOE`, `overrideReason` |
| Derived | `teachingDoeModel2026_27`, `assignedTeachingDOE`, `doeAssignedTeachingDOE`, `teachingSummary2026_27` |
| Roles | `managedRoles2026_27`, `roleMigration2026_27` |
| Availability | `awayFromCampusRecords`, `awayFromCampusSource`, `awayFromCampusImportedAt`, `awayFromCampusImportedBy` |
| Summary import | `facultySummary2026_27`, `facultySummarySource2026_27`, `facultySummaryStatus2026_27`, `facultySummaryImportedAt`, `facultySummaryImportedBy` |
| Workload policy | `workloadPolicy2026_27`, `workloadPolicySource2026_27`, `workloadPolicyImportedAt2026_27`, `workloadPolicyImportedBy2026_27` |
| Provenance | `bulkImportedAt`, `bulkImportedBy`, `updatedBy`, `updatedByName`, `updatedAt` |

**DOE resolution order** (`faculty-doe.js`): approved override → contract DOE →
`null` (never silently zero). When a policy bundle is supplied the canonical
engine is used instead and the result carries `policyVersionId`, `ruleId`, `ruleKey`.

### `faculty_groups/{groupId}`

HICC-owned swap groups. `name`, `ownerUid`, `courseIds`, `memberUids`,
`updatedBy`, `updatedByName`, `updatedAt`, `createdAt`.
Invariant: `ownerUid` must be an active `hicc` account and must be a member.

## 3. Scheduling

### `sessions/{sessionId}` — private source of truth

| Field | Type | Notes |
| --- | --- | --- |
| `course`, `courseName` | string | course code and title |
| `year`, `semester`, `week` | number / string / number | academic placement |
| `date`, `start`, `end` | string | `YYYY-MM-DD`, `HH:MM` |
| `timeUnknown` | bool | unknown time must never be treated as 00:00 |
| `type` | string | `LAB`, `LECTURE`, `SRL`, … |
| `topic`, `room` | string | LAB topic is LAB-office owned |
| `instructor`, `instructorNames` | string / list | public display projection |
| `facultyIds` | list\<string\> | private linkage to `/faculty` |
| `assignments` | list\<map\> | `ucid`, `facultyId`, `name`, `role`, `topic`, `creditedHours`, `doeRate`, `doeCredit`, `source` |
| `approvalRequestId`, `approvalRevision` | string / number | set when applied from an approved request |
| `sourceWorkbook`, `sourceSchema`, `bulkImportedAt`, `bulkImportedBy` | | import provenance |
| `updatedBy`, `updatedByName`, `updatedAt` | | actor stamp |

**Office field ownership**

| Role | May change |
| --- | --- |
| ADC | course, courseName, year, semester, week, date, start, end, timeUnknown, type, room, topic — but topic only when `type == 'LAB'` |
| LAB | `topic` **only**, and only when `type == 'LAB'` on both sides |
| ADFA / admin | instructor assignments, plus general repair |

### `calendar_sessions/{sessionId}` — public projection

Exactly these keys, no others (`calendarKeysValid`): `sessionId`, `course`,
`courseName`, `year`, `semester`, `week`, `date`, `start`, `end`, `timeUnknown`,
`type`, `topic`, `room`, `instructorNames`, `instructor`.

**Invariant:** for every field above, the calendar value must equal the source
value. Private assignments, faculty identifiers and AFC data are never copied.
A stale display string is fixed at the source writer, never silently diverged
during calendar repair.

## 4. Multi-office change approval

A routed request is one logical change spread over five collections.

### `change_requests/{requestId}` — public half
`requestSchema` (`office-routing-v1`), `requesterUid`, `requesterName`,
`requesterRole`, `sessionId`, `requestType` (`session_edit` | `faculty_swap`),
`scope`, `groupId`, `groupName`, `status`, `revision`, `basePublic`, `patchPublic`
(both restricted to the public session field set), `currentFacultyName`,
`proposedFacultyName`, `editableFields`, `requesterMessage`, `reason`, `course`,
`date`, `topic`, `requestedAt`, `updatedAt`, `withdrawnBy`, `withdrawnAt`,
`appliedRevision`, `appliedAt`.

**Status machine:** `pending` → (`update_required` → `pending`) → `approved`
→ applied · or → `rejected` · or → `withdrawn`.

### `change_request_workflow/{requestId}` — routing
`requestId`, `revision`, `requiredOffices` (subset of `adc`,`lab`,`adfa`),
`hasFacultyChange`, `finalType`, `scopes` (office → field list),
`scopeSignatures` (office → signature), `updatedAt`.

### `change_request_approvals/{requestId}_{office}` — per-office decision
`requestId`, `office`, `revision`, `fields`, `scopeSignature`, `status`,
`decidedBy`, `decidedByName`, `decidedAt`, `message`, `updatedAt`.

**Invariant:** a decision only counts when `status == 'approved'` **and** `fields`
and `scopeSignature` still match the workflow. Changing a draft invalidates prior
approvals by changing the signature — approvals are never silently reused.

### `change_request_private/{requestId}` — private target
`requestId`, `requesterUid`, `revision`, `assignmentChange`
(`assignmentIndex`, `from` / `to` each `{facultyId, candidateKey, kind}`),
`updatedAt`. Readable by ADFA approvers only.

### `change_request_audit/{requestId}` — append-only
`requestId`, `event`, `revision`, `status`, `office`, `message`,
`changedFields`, `changedBy`, `changedByName`, `changedAt`.
`update`/`delete` denied.

**Spark constraint.** A request containing a faculty change must be finalised by
ADFA after the other required offices approve — there is no server-side
transaction available on the Spark plan. Migration marker:
`UCVM_DB_MIGRATION_REVISIT: spark-client-finalizer`.

### `workflow_notifications/{id}`
`recipientOffice`, `kind` (`request_assigned`, `request_resubmitted`,
`office_decision`, `request_applied`, `request_withdrawn`,
`assignment_recheck_required`), `requestId`, `sessionId`, `course`, `date`,
`start`, `end`, `type`, `topic`, `facultyDisplayName`, `message`, `createdAt`,
`readBy` (starts empty; only the reader's own uid may be appended).

## 5. Faculty workload (DOE) and AFC

### `afc_requests/{requestId}`
`requesterUid`, `facultyId`, `reportToUid`, `status`, `workDays`, `startDate`,
`endDate`, `appointmentType`, `rank`, `reason`, `purposeDestination`, `coverage`,
`facultyName`, `reportsTo`, `contactAddress`, `contactPhone`,
`applicantSignature` (`uid`, `attested`, `signedAt`), `reportToSignature`,
`adminSignature`, `rejectionReason`, `withdrawnBy`, `withdrawnAt`,
`pdfChunkCount`, `pdfSha256`, `pdfByteLength`, `submittedAt`, `approvedAt`,
`updatedAt`.

**Status machine:** `pending_report_to` → `pending_admin` → `approved` ·
or → `rejected` · or → `withdrawn`.

**Privacy:** another faculty member may learn only binary availability
(`Available` / `Unavailable`). Never the reason, never the date range.

### `afc_requests/{requestId}/pdf_chunks/{index}`
`index`, `base64`, `sha256`. Creatable only while the parent is `approved` and
only when `sha256` matches the parent's `pdfSha256`. Immutable afterwards.

### `afc_audit/{id}` — append-only
`changedBy`, `changedAt`, `action`, `requesterUid`, `reportToUid`, plus context.

## 6. Derived data (`settings/*`)

All rebuildable. `index-maintenance.js` owns the rebuild.

| Document | Visibility | Contents |
| --- | --- | --- |
| `settings/system_state` | all ready users (read) | write lock: `teachingDataWriteLocked`, `maintenanceMode`, `activeImportId`, `maintenanceOwnerUid`, `maintenanceOwnerName`, `maintenanceStartedAt`, `lastCompletedImportId`, `lastCompletedAt` |
| `settings/faculty_index` | admin | sanitized faculty search index |
| `settings/schedule_stats` | admin | per-course/term aggregates |
| `settings/faculty_swap_index` | ready non-office | **sanitized** swap candidates — see §8 |
| `settings/faculty_swap_map` | admin | private key → `facultyId` resolution |
| `settings/faculty_summary_2026_27` | general | 2026-27 summary import |

**System-state lock protocol.** Acquiring the write lock requires an existing
`bulk_import_jobs/{id}` in `APPLYING` owned by the same actor. Releasing it
requires that job to have reached `COMPLETED` or `RESTORED`. This makes an
interrupted import recoverable rather than permanently locking teaching writes.

## 7. Audit trail

| Collection | Writer | Append-only |
| --- | --- | --- |
| `session_change_log` | ADFA admin, or ADC/LAB office session audit | **yes** |
| `faculty_change_log` | ADFA admin | **yes** |
| `account_audit` | general, or HICC for its own group | **yes** |
| `audit_events` | nobody (service-written only) | **yes** |
| `afc_audit` | any ready user, self-stamped | **yes** |
| `change_request_audit` | routing participants | **yes** |

`session_change_log` / `faculty_change_log` shape: `action`, `override`,
`requestId`, `sessionId`, `course`, `date`, `topic`, `instructors`, `changes`,
`changedBy`, `changedByName`, `changedByEmail`, `changedAt`.

**A correction is a new event.** `update` and `delete` are denied on all six.

## 8. Sanitized swap-candidate projection

This is the model that lets a faculty member reference a colleague without
reading `/faculty` or listing `/users`.

**`settings/faculty_swap_index`** — readable by any ready non-office account.
Contains **only**:

| Field | Notes |
| --- | --- |
| `entries[].key` | opaque candidate key (not a UCID, not a uid) |
| `entries[].name` | display name only |
| `entries[].unavailableRanges` | **coarse** availability windows, no reason |
| `entries[].conflicts` | course + time only, which timetable users already see |
| `generatedAt` | rebuild stamp |

**Forbidden in this document:** `ucid`, `email`, `facultyId`, any DOE value, any
AFC reason, any HR field.

**`settings/faculty_swap_map`** — admin-only. Maps `key` → `facultyId` so ADFA can
resolve a sanitized key at approval time and re-check live availability before
applying.

### `settings/people_index` — HICC people picker projection

Added to close the `/users` enumeration gap. The HICC group-swap picker needs to
offer colleague names, but it previously read `/users` directly, which also
exposed `email`, `facultyId` and account state.

| Field | Notes |
| --- | --- |
| `entries[].uid` | account uid |
| `entries[].name` | display name |
| `entries[].role` | `hicc` / `visc` / `faculty` only |
| `generatedAt` | rebuild stamp |

**Forbidden:** `email`, `facultyId`, `active`, `mustChangePassword`, office fields.
Readable by ready faculty-role accounts; writable by ADFA admin only.

session or audit rows.

## 11. Known limitations

These are recorded rather than hidden. Each is tracked in the audit report.

1. **`mustChangePassword` is self-cleared.** `selfPasswordCompletion()` lets the
   account holder flip it. It is UI guidance, not a control. Do not rely on it.
   Replacing it with a trusted invitation or institutional SSO is still open.
2. **Rule evaluation budget is close to Firestore's 1000-expression ceiling.**
   Adding further `getAfter()`/`existsAfter()` calls requires an evaluation-cost
   review first. `tests/rules-evaluation-budget.test.js` pins the current count.
3. **Spark plan has no server-side transaction**, hence the client-side finaliser
   and its migration marker.
4. **The legacy request shape is still writable.** A pre-routing request can still
   be approved, but only when the paired session write happens in the same commit
   (`legacyAppliedCompanionWrite`). The shape should eventually be retired once no
   pre-routing records remain.
