# PAWS P0 W1D — Firestore Authority Matrix

**Status:** local feature-branch containment candidate for Architect #6 review; rules are not deployed. **Baseline:** `feature/beta-w1d-firestore-authority-containment` from W1C `916a90cc2e3e9f55c01e26ace6a14f21c7d2cca9`.

## Decision boundary

The target authority for canonical business writes is Firebase Authentication → trusted PAWS University API → server authorization → narrow VetMed-Ops procedures. W1D removes browser Firestore write paths for SQL-canonical data and makes rules deny those writes independently of maintenance metadata. It does not enable SQL writes or activate W1C. Firestore users/groups and information-center functions remain only where they are separate. UserProfile/BaseRole overlap is unresolved for Architect #6.

## W1D invariants and residual decisions

- Rules deny `sessions`, `faculty`, `session_change_log`, `faculty_change_log`, `afc_requests` including nested PDF chunks, `afc_audit`, `audit_events`, and generic derived `settings` writes independent of `settings/system_state`.
- `change_requests` remains a separate Firestore proposal path; its browser approval/apply module is not loaded. A denied session write makes a batched proposal + session apply fail atomically.
- Firestore Auth, User Management and group capabilities were not migrated. `users.role` and Firebase `faculty` role fields versus SQL `UserProfile.BaseRole` need Architect decision; no mapping is invented.
- `public_info` remains announcement-only. `public_schedule/ccc_events` is a read-only browser projection with an external Firestore REST writer whose source should move to an approved SQL/AFC rebuild before cutover.
- Maintenance metadata may still change through its separate narrow state machine, but cannot reopen any canonical write path.
- W1C remains independently default-off: AFC single/batch and session PATCH capabilities remain false; no Firestore fallback is added to `paws-data-client.js`.
- No live Firestore readback, synthetic write, rules deployment, Firebase/config mutation, SQL/Azure mutation, migration 016, service/deployment, PR, merge or `main` update occurred in W1D.
